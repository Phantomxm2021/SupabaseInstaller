# 服务配置页重排设计

## 已确认的方向

采用 **A：预设侧栏 + 服务分组**。该方案保留现有深色视觉和绿色强调色，重新组织新建项目向导中“Preset & services”步骤的信息层级。

## 目标

- 让用户先理解并选择服务预设，再对预设进行微调。
- 让服务按功能分组，减少目前双栏长列表造成的视觉跳读。
- 在编辑预设后明确告知其已转为 Custom，避免状态歧义。
- 保留所有现有服务、必需项约束、开关交互与向导底部操作。

## 布局

页面顶部保留步骤进度、标题和一句简短说明。主内容采用左右两栏：

- 左栏为垂直预设列表：Lightweight、Standard、Full、Custom。当前预设以绿色边框与深绿色填充突出，并带有一行简短说明。
- 右栏显示当前预设的启用服务与可调整项。服务按“核心服务”“开发体验”“数据与扩展”“可观测性”等职责分组，每组包含紧凑的服务行和右侧开关。
- 右栏标题显示当前预设及启用服务数量；底部提供一条内联提示：任何服务开关变化都会把预设变为 Custom。
- 页面底部保留 Cancel、Back、Review、Continue 的既有操作层级；Continue 继续使用主绿色按钮。

## 视觉规则

- 使用当前的深色背景、浅色正文、低对比描边与 Supabase 绿色。
- 预设卡片不再占据大面积内容区；它们作为左侧紧凑导航。
- 必需服务在名称旁以低调的“必需”标签说明，并维持不可关闭或现有依赖行为。
- 服务行高度、圆角、边框与间距统一；分组标题用小号大写/字距区分，不引入额外的强色。

## 交互与响应式

- 选择预设会更新右栏服务状态和服务数。
- 修改可编辑开关后，选中预设切换为 Custom；提示持续可见。
- 窄屏下左右两栏顺序堆叠：预设列表先展示，服务分组随后展示。

## 验收标准

- 用户无需横向扫视两列，即可找到某一预设和对应服务。
- 页面首屏清楚表达“先选预设、再微调”的工作流。
- 所有服务仍可见，且必需项与可选项在视觉和交互上可区分。
- 原有向导导航与后端配置语义不改变。
